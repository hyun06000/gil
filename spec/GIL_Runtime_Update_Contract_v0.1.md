# GIL Runtime Update Contract v0.1 — 고정 실행기와 다음 연결 적용

작성일: 2026-10-23. **후속 설계안 / 제품 미구현 / 설치·게시 승인 아님.**

배포 명세 §9를 보완한다. 현재 Plugin의 직접 Core 실행 경로를 이미 변경한 것으로 읽지 않는다.
실험은 Node 실행기와 합성 서버를 사용했다. 사용자 설치본에 Node를 요구하지 않는 기존 자족형
native 계약, unsigned 채널의 버전별 승인, 저장·이관 계약은 유지한다.

## 1. 문제와 결정 범위

세 문제를 구분한다.

1. **Project 저장 보호:** OneDrive 경로에서 `.gil` 보호 DACL 재열기 거절이 보고됐다.
   동기화 주체가 DACL을 바꿨다는 인과는 미확정이다. Windows 작성 계약의 위치 검사·보존·
   권한 변경 요청 금지로 다루며 업데이트 실행기가 이를 수리하지 않는다.
2. **Host 설치 수명:** Windows 공식 제거/교체에서 cache 삭제 access denied가 보고됐다.
   옛 cache의 실행 중 프로세스도 관측됐지만 모든 실패 원인을 파일 잠금으로 확정하지 않는다.
   제거·설치 성공이나 UI Disable의 수명 효과를 가정하지 않는다.
3. **Core 선택과 연결 수명:** 옛 실행 파일을 지우지 않고 다음 연결의 Core만 바꿀 수 있는지
   별도 합성 시험을 수행했다. 이 문서가 채택하는 **구현 검토 방향**은 고정 실행기 + 불변
   버전별 Core + 명시적 선택 + 새 연결에서 적용이다. 초기 설치·배포 원자성은 별도 미완이다.

제품 코드를 지우고 재다운로드하는 방법, cache 손편집, 기존 프로세스 강제 종료는 업데이트
기본 경로로 채택하지 않는다. Host가 관리하는 Plugin cache를 GIL이 직접 변경해서도 안 된다.

`d25290d33f106efba93c29b8138f32ff28317976e944337a159de3c2bbb8c6ce`, v2

대화 원문은 수록하지 않는다. 현장 근거의 보존이 불완전하므로 **재연결 관측 확인 / 종합 인수 미완**이다.

준비 과정의 TOML 파싱 오류, PowerShell 읽기 전용 변수명 충돌, MCP 줄바꿈 직렬화 오류는
하네스 결함으로 별도 기록한다. MCP/GIL 제품 결함으로 세지 않으며 최종 성공으로 첫 실패를 지우지 않는다.

## 3. 역할과 수명 계약 (구현 시 충족할 요구사항)

- **Host 관리 Plugin:** manifest·Skill·실행기 설치와 제거는 공식 Host 경로가 소유한다.
  Core 업데이트 설계가 Host Plugin 갱신 API 또는 cache 조작 권한을 대신하지 않는다.
- **고정 실행기:** 연결 시작 때 검증된 선택 기록을 읽어 한 Core를 실행하고 해당 연결에는
  그 버전을 고정한다. 설치 cache의 실행기를 매 Core 업데이트마다 지우거나 덮어쓰지 않는다.
- **버전 저장소:** GIL이 명시적으로 소유하는 별도 영역을 설계한다. 실제 경로·권한·Host 정책
  허용 여부는 미결이다. 사용자 `.gil`이나 임의 개발 checkout, 기존 Host cache를 저장소로 쓰지 않는다.
  한번 공개한 버전 bytes는 불변이며 같은 version에 다른 bytes를 덮어쓰지 않는다.
  현행 배포 명세 §8.1의 bundled Core 실행과 달라지는 부분이므로, 외부 버전 저장소를 제품에
  적용하기 전에 공식 Host 허용 범위와 배포 계약 개정을 명시적으로 검토해야 한다.
- **업데이트 조율:** 승인·출처·digest·호환성 검증 뒤 선택을 바꾼다. 선택은 신규 연결에만 적용된다.
  배포 완료, 선택 완료, 연결 적용 완료, 화면 확인은 서로 다른 상태다.
- **사용자 Project:** 업데이트 승인과 Project 쓰기/이관 승인은 다르다. 실제 자료로 probe하지 않고
  파일 교체 때문에 `.gil` ACL·기록·저장 형식을 바꾸지 않는다.

`config/mcpServer/reload` 반환 성공이나 manifest의 최신 버전 표시는 새 Core 실행의 증거가 아니다.
새 연결이 보고하는 실행 버전/빌드 식별과 실제 도구 응답으로 확인한다. PID는 시험 보조 증거다.
별도 App Server의 새 thread를 실제 Desktop의 모든 새 대화 동작으로 일반화하지 않는다.

## 4. 호환성과 업데이트 상태

```text
후보 준비 → 무결성·호환성 검증 → 버전별 승인 → 신규 연결용 선택 완료 → 새 연결 적용 확인
                                                       기존 연결은 기존 판 유지
```

실행기는 Core·MCP/tool schema·저장 읽기/쓰기 범위·Manual·내장 UI·현재 로드된 Skill과의
호환을 확인해야 한다. 단순 hash 일치 시험은 의미적 호환성의 증명이 아니다. Skill 또는
실행기 자체의 변경이 필요하면 Core-only 업데이트로 처리하지 않고 공식 Plugin 교체 경로로
분리한다. 기존 대화에 로드된 Skill이 새 Core에 맞게 자동 갱신된다고 가정하지 않는다.

다중 버전이 같은 Project를 열 수 있는 조건은 실제 잠금·저장 호환 시험으로 정한다. 해당
검수 전에는 이를 지원한다고 말하지 않는다. storage migration은 별도 승인·백업·복구 계약을
따른다. Windows format-4→5 이관 거절을 이 문서로 풀지 않는다.

## 5. 실패·신뢰·정리 경계

- publisher/채널 인증과 다운로드 digest를 구분한다. unsigned opt-in은 버전별 승인을 유지한다.
  이번 설계가 무승인 자동 업데이트나 현재 미해결 배포 게이트의 해소를 의미하지 않는다.
- 준비·probe·호환성 실패 또는 권한 거부 시 기존 선택·기존 프로세스·사용자 기록을 보존한다.
  승격, 보안 해제, 임시 경로 변경으로 정책을 우회하거나 실패를 무한 재시도하지 않는다.
- 선택 공개의 중단·부분 쓰기·동시 writer·디스크 고갈 경계를 별도 설계한다. 지원하지 않는
  rename을 일반 덮어쓰기로 바꿔 제품의 안전성 요구를 낮추지 않는다. E4 일반 쓰기는 시험 한정이다.
- ACL·reparse·hardlink·TOCTOU, 경로 소유권, 최소 권한과 제한 토큰에서 실제 쓰기 가능성을
  검증한다. 일반 runner에서 가능했던 원시 연산을 Codex 에이전트 환경에서도 된다고 가정하지 않는다.
- 새 Core에 세션을 넘긴 뒤 오류가 났다고 자동으로 옛 writer를 재실행하지 않는다. Project 변경
  가능성이 있으면 멈춰 상태를 확인한다. rollback은 호환성과 사용자 승인을 따로 검토한다.
- 옛 버전 삭제는 업데이트 성공의 선행 조건이 아니다. 자동 GC·stale lock 회수·실행기 자체 교체는
  별도 설계 전까지 하지 않는다. 정상 종료·잔존 프로세스 관측과 강제 종료를 구분한다.

## 6. 비개발자 UX와 최초 도입

제품 목표는 사용자의 한 문장 요청과 필요한 정확한 승인이다. 기본 경로에 PowerShell,
개발 도구 설치, 경로/JSON 편집, OneDrive 비활성화, ACL 수정, 기존 프로세스 강제 종료를
요구하지 않는다. 실험의 Node 사용은 사용자 의존성 결정이 아니다.

필수 안내 상태: `후보 준비됨`, `다음 연결부터 적용 예정`, `현재 연결은 이전 버전`,
`새 연결 적용 확인`, `차단됨`. 승인을 받은 뒤에도 정책 차단은 중단·설명한다. 권한 요청을
자잘한 구현 오류마다 사용자에게 되돌리지 않되 허용 범위 확대를 자동 승인으로 해석하지 않는다.

기존 direct-Core Plugin에서 고정 실행기 Plugin으로 옮기는 **최초 1회 설치/교체**는 아직
해결되지 않았다. 고정 실행기 역시 실행 파일이므로 자기 업데이트·제거 때 같은 수명 문제가
생길 수 있다. 공식 Host 지원·패키징·native 실행기 구현을 검토하고 실제 사용자 검수로 닫는다.
두 GIL 서버를 동시에 노출하는 병렬 설치를 기본 우회로로 사용하지 않는다.

현재 대화의 즉시 갱신 또는 무조건적인 앱 재시작을 약속하지 않는다. Host에서 새 연결이
필요하면 이유와 적용 상태를 알리고, 실제 검수된 최소 사용자 동작만 제안한다.
