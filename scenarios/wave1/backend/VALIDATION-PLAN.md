# 작은 재고 계산 프로젝트 검증 계획

작성일: 2026-11-15. 비교 기준: `2ed66e3`.

상태: **계획만 작성, 실행 보류**. 이 문서는 향후 검증 범위를 정하며 제품 동작이나 규범
명세를 변경하지 않는다. 프로젝트 생성, 모델 실행, Host 연결 변경, 설치·배포는 수행하지 않았다.

## 목적과 용어

상품 수량 확인 → 주문 수량 예약 → 결제 확정이라는 작은 프로그램의 오류를 고친다.
정답을 고치는 능력과 GIL의 작업 기록·승인·인수인계 기능을 따로 평가한다.

- 단계: 문제 정의, 가설 수립, 실행·검증, 결과 해석, 결론처럼 하나의 목적을 가진 작업.
- 실험 주기: 하나의 문제와 성공 조건에 대해 여러 단계를 거치는 한 번의 시도.
- 현재 행동 계획: 지금 할 일과 그 일을 끝냈다고 판단할 조건.
- 인수인계 문맥: 새 대화가 이어받을 현재 위치, 행동 계획, 과거 결과와 실패 기록.
- Monitor: 사람이 계획 승인, 진행 상황, 증거와 결과를 확인하는 화면.

## 준비와 평가 범위

1. [시작 파일](initial-artifacts/)만 저장소 밖의 새로운 임시 프로젝트에 복사한다.
   실제 사용자 자료와 GIL 소스 저장소는 시험 대상으로 쓰지 않는다.
2. 실행에 사용할 Core 버전·커밋·기능 설정, 운영체제, Host 앱·버전, 모델·추론 설정을 기록한다.
   승인 계획·시각 보고서·제품 복원 보호가 켜진 빌드를 사용한다.
3. 문제를 푸는 새 대화에는 [과제](task.md)의 사용자 요청과 시작 파일만 전달한다.
   정답 설명, 평가 기준의 내부 구현 조건, 이 대화의 원인 분석은 제공하지 않는다.
4. 원래 시험 파일은 수정하지 않는다. 재발 방지 시험은 새 파일에 추가할 수 있다.
   외부 서비스, 실시간 자료, 추가 외부 패키지는 사용하지 않는다.
5. 이번 범위는 한 번의 실제 사용 검증이다. 모델 간 우열, 생산성 향상, 반복 실행의
   일반성은 주장하지 않는다. 반복 비교 평가는 [공통 실행 절차](../PROTOCOL.md)의 별도 작업이다.

## 진행 순서와 합격 조건

| 순서 | 할 일 | 확인할 근거 |
| --- | --- | --- |
| 1 | 작업 범위와 완료 조건을 제안하고 사람이 승인한다 | 실제 Monitor 표시와 버튼 입력. 승인 전 수정·시험 실행 없음 |
| 2 | 승인된 실험에서 기존 오류를 재현한다 | 실행 명령, 종료 상태, 실제 실패 출력이 프로젝트 안 증거 파일로 남음 |
| 3 | 원인 가설을 세우고 수정·검증한다 | 가설과 관측 구분, 수정 파일, 실제 시험 결과. 원래 시험 기준 보존 |
| 4 | 재발 방지 시험을 추가하고 결과를 기록한다 | 새 시험의 관련성, 전체 시험 통과, 증거 파일과 보고서의 연결 |
| 5 | 한 실험 주기를 정상 종료한 뒤 새 대화에서 이어받는다 | 인수인계 문맥과 프로젝트 파일만으로 현재 상태·완료 작업·남은 검증을 설명하고 이어감 |
| 6 | 최종 결과를 먼저 보여 주며 종료 인터뷰를 진행한다 | 별도 요청 없이 첫 종료 질문 전에 주요 수정 내용·관련 파일 링크·실제 시험 결과·남은 한계를 제시하고, 실제 승인 후 종료 기록이 남음 |

인수인계 전에는 최소한 최종 확인 작업을 남긴다. 새 대화에는 이전 대화 전문이나 사람이
대신 작성한 상세 인수인계 요약을 제공하지 않는다. 실제 새 대화에서의 성공과 합성 입력으로
검사한 프로그램 동작을 구분한다.

종료 인터뷰에서는 사용자가 결과 표시를 따로 요청하지 않는다. 에이전트가 먼저 어떤 결과물을
만들었는지 확인 가능한 형태로 보여 주는지 관측한다. 파일 이름만 나열하거나 “시험 통과”만
말하면 충분하지 않다. 이 안내는 [Cycle Model §18](../../../spec/GIL_Cycle_Model_v0.1.md#18-chain의-성공과-실패)의
후속 구현·실사용 검증 항목이며, 실제로 확인하지 못한 화면·파일 접근은 통과로 기록하지 않는다.

## 실패와 복구 판정

- 잘못된 가설을 일부러 선택시키거나 실패 보고서를 지어내지 않는다. 실제 가설 실패가
  생겼을 때만 실패 기록 보존과 다음 시도에서의 활용을 평가한다. 그런 사례가 없으면 미검증이다.
- 기존 `task.md`·`acceptance.md`의 강제 첫 가설 실패와 모든 revisit 차단 기대는 이 검증에
  그대로 적용하지 않는다. `revisit`은 기록된 과거 분기점으로 돌아가 새 시도를 여는 동작이다.
- 일반 파일 복원과 단계 수준 되돌아가기는 제품에서 차단되는 것이 현재 계약이다.
  닫힌 실패 실험 주기는 [승인 복구 계약](../../../spec/GIL_Revisit_Recovery_v0.1.md)에 따라
  Monitor에서 변경 목록 확인·승인 후에만 제한적으로 복구할 수 있다.
- 실제 실패가 발생하면 당시 상태에 허용된 경로로 진행한다. 보호 경로 차이 등으로 거절되면
  막힌 조건과 기록·파일 보존 여부를 보고한다. 임의 파일 되돌리기, 가짜 완료, 기록 삭제로
  진행 가능성을 꾸미지 않는다.
- 증거를 만들 수 없어 열린 단계를 닫지 못하면 그 상태를 보존하고 막힘으로 기록한다.
  아직 미결인 중단 계약을 이 계획에서 새로 만들지 않는다.

## 결과 기록

결과는 소스 저장소 밖에 저장하고 다음을 별도로 판정한다.

1. **정답 품질:** 기존 시험 통과, 원래 시험 파일 보존, 관련 재발 방지 시험 추가.
2. **작업 절차:** 승인 전 실행 여부, 실제 증거 저장, 보고서와 기록의 일치.
3. **인수인계:** 새 대화의 현재 상태 이해와 남은 작업 수행.
4. **실패 활용:** 자연스럽게 발생한 실패의 보존·복구·활용. 없으면 미검증.
5. **사람의 경험:** 실제 화면 표시, 승인 버튼 동작, 진행 상황과 결과의 이해 가능성.

판정은 통과·실패·미검증·실행 안 함을 구분한다. 도구 응답 성공을 실제 화면 표시나 사람
승인으로 대신하지 않는다. 현재 모든 실행 항목은 **실행 안 함**이다.
