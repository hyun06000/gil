# 훅 없는 새 세션 재개

GIL의 관리 단위는 선택된 프로젝트다. 새 세션에서 “기존 보고서에 시각자료를 추가해 줘”라고 요청해도
먼저 `gil_context`로 현재 계획·Cycle·Step·계약을 읽고, 실제 열린 Verify에서 파일을 만든다.
요청에 GIL이라는 단어가 없어도 프로젝트 산출물 작업은 재개다. 새 세션만을 이유로 새 Cycle을
만들지 않으며, 새 목적을 완료된 계약이나 범위가 다른 열린 Verify에 끼워 넣지도 않는다.

## 프로젝트에 남는 안내

- 새 CLI/MCP `start`는 프로젝트 잠금 아래 Codex `AGENTS.md`와 Claude `CLAUDE.md`의 끝에
  `GIL PROJECT RESUME v1` 블록을 추가한 뒤 최초 Snapshot을 만든다. 기존 `AGENTS.override.md`가
  있으면 Codex가 우선하는 그 파일을 사용한다. 기존 앞부분 bytes·개행·권한은 다시 쓰지 않는다.
- 라이브러리의 저층 생성 API는 자동 안내를 추가하지 않는다. 제품 CLI/MCP 진입점의 동작이다.
- 기존 프로젝트의 `context`·`status`는 안내를 설치하지 않는다. 다음 정상 `gil_open Verify`가
  먼저 기록된 뒤 같은 잠금 아래 추가하며, 다음 Verify Snapshot이 그 변경을 담는다.
  과거 Snapshot·승인·보고서·실행 이력은 다시 계산하거나 수정하지 않는다.
- 이미 열린 Verify에서는 읽기 호출만으로 안내를 추가하지 않는다. Agent가 그 쓰기 경계 안에서
  기존 안내를 보존해 채택하거나 다음 Verify open을 따른다. 빈 Step을 만들어 설치하지 않는다.
- 선택한 루트는 Core와 같은 정규 경로로 고정한다(macOS `/var` 별칭 등). 안내 파일 자체의
  symlink/hardlink는 따라가지 않으며 다른 프로젝트를 검색하지 않는다.
- 동일 블록은 반복 추가하지 않는다. 편집된/불완전한 GIL 블록, UTF-8이 아닌 파일, 24 KiB 예산 초과,
  비어 있는 override(기존 AGENTS를 가릴 수 있음), 링크·특수 파일·파일 잠금 경합은 보존하고
  `pending/review_required`로 표시한다. 사용자가 편집한 블록을 새 판으로 몰래 교체하지 않는다.
- 추가 실패가 이미 성공한 Step open을 취소한 것처럼 표시하지 않는다. 현재 상태와 남은 파일을
  읽고 안전한 다음 행동을 선택한다. 파일 추가만으로 본래 요청의 관측·증거를 채웠다고 하지 않는다.

안내는 일반 Artifact다. 설치용 예외·Snapshot 제외 목록·전역 bootstrap 폴더를 만들지 않는다.
정상 복구로 안내가 없던 Snapshot으로 돌아가면 안내도 없어질 수 있다. 당시 Snapshot을 수정하지 않고
다음 합법적인 Verify에서 다시 채택한다. 외부 편집기까지 파일 잠금을 강제하는 기능은 아니다.
중단된 append의 남은 bytes는 보존하며 자동으로 잘라 내거나 덮어쓰지 않는다.

## 기존 프로젝트의 최초 채택과 비간섭

새 서버의 공통 MCP 지침은 파일을 만들기 전 **사용자가 선택한 작업 루트**의 프로젝트 안내와 `.gil`
흔적만 읽도록 한다. 일반 폴더에는 GIL을 시작하거나 등록하지 않는다. HOME·구형 registry·다른 프로젝트를
검색하지 않으며, 파일 없는 웹 조사·무관한 질문·외부 작업에는 GIL 단계나 종료 조건을 요구하지 않는다.
기존 GIL 프로젝트라고 확인되면 `gil_context`를 먼저 읽고 실제 기록 위치에서 이어간다.

기존 프로젝트에 안내 파일이 없고 Host가 MCP instructions를 모델에 전달하지 않으면 최초 자동 인지를
보장할 수 없다. 그 경우 해당 프로젝트를 한 번 명시적으로 재개해 합법적인 Verify에서 안내를 채택한다.
업데이트 installer가 사용자 프로젝트들을 순회하거나 기록·Snapshot을 일괄 수정하지 않는다.
Windows에서 기록이 개인 앱 데이터에 있는 구형 프로젝트도 같은 최초 채택 제한을 갖는다.

복사본·worktree·하위 폴더에서는 Host가 선택한 실제 루트와 기록을 확인한다. 안내 파일만 복사됐다고
원래 프로젝트의 기록을 쓰거나 `.gil`을 복제하지 않는다. 다른 프로젝트에 전역 안내나 훅을 설치하지 않는다.
연결/기록이 손상되거나 접근할 수 없으면 프로젝트 쓰기 전에 설명하고 해결하며 일반 작업으로 몰래 전환하지 않는다.

## Host 로딩과 검증 범위

- [Codex 공식 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md): 새 실행에서 프로젝트 안내를
  발견한다. override 우선순위, 지침 크기 제한, Git 루트/현재 디렉터리와 하위 지침에 영향을 받는다.
- [Claude 공식 안내](https://code.claude.com/docs/en/memory): 프로젝트 CLAUDE.md를 세션 시작에 읽는다.
  실제 Desktop Code 탭의 선택 폴더·worktree·지침 설정에서 로딩 여부를 별도로 확인한다.

따라서 **안내 파일 생성·Core 프로토콜 통과**와 **실제 Host 로딩·모델 준수**는 다르다. 프롬프트는 파일 쓰기를
강제 차단하지 않는다. 이 변경은 전역·프로젝트 로컬·Plugin·Skill 훅을 설치하지 않으며 보안 설정을 바꾸지 않는다.
필드테스트는 두 Host에서 새 세션 → GIL을 언급하지 않은 기존 산출물 수정 요청 → 첫 파일 도구 전 context →
현재 계약/새 범위 판단 → 적법한 Verify → 파일 증거 순서를 확인한다. 대조군은 일반 프로젝트와 무관한 질문이다.
