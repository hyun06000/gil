# Monitor 기본 화면 간결화 — 개선 전후 캡처 (2026-11-15)

Monitor Model §1.1·§1.2 를 공용 화면(`ui/`)에 적용한 결과를 **같은 fixture·같은 상태**에서
개선 전(`before-*`)과 개선 후(`after-*`)로 찍은 것이다. 헤드리스 Chrome 으로 fixture Host
(`ui/host.js`)를 띄워 찍었으므로 실제 Host(Codex·Claude Desktop) 화면이 아니다. 판독 검수와
실제 Host 의 전체 화면·채팅 병행·재열기 회귀 확인은 사용자 몫이며, 이 캡처로 통과 처리하지 않는다.

| 파일 | fixture | 상태 | 너비 |
| --- | --- | --- | --- |
| `*-reading-one-760` | reading-one | 기본 화면(선택 없음) | 760px |
| `*-reading-one-420` | reading-one | 기본 화면 | 420px(좁은 화면) |
| `*-dense-760` / `*-dense-420` | dense | 기본 화면 | 760 / 420px |
| `*-first-interview-760` / `-420` | first-interview | 첫 인터뷰, `world=dirty` | 760 / 420px |
| `*-reading-one-760-selected` | reading-one | `step:C3/S1` 선택 → 카드·detail | 760px |
| `*-reading-one-760-stale` | reading-one | 다시 읽기 실패(`busy`) → 마지막 확인 상태 | 760px |
| `*-dense-760-cycle` | dense | `cycle:C4` 사이클 보고서 선택 | 760px |
| `*-reading-one-760-open` | reading-one | 「기록 상세」를 펼친 상태 | 760px |

달라진 것(기본 화면):

- 지금 하는 일: 짧은 제목 + 실제 상태(진행 중 / 다음 단계 대기 / 완료·판정). 상태 문장이 제목 자리를 차지하지 않는다.
- 어디까지 왔는가: `실험 C3 · 구현·검증 진행 중` 한 줄 + Graph. 기록 개수·식별자(`cycle:`/`step:`)·관측 시각·파일 상태 원문·안내문은 `<details>` 「기록 상세」 뒤로.
- 지금 할 일: 열린 행동 계약의 다음 행동. 완료 조건이 위의 성공 기준과 같은 문장이면 반복하지 않는다.
- 파일 상태가 기준과 다르거나 보지 못했을 때만 경고 한 줄. 정상(`clean`)은 기록 상세 안의 한 줄이다.
- 다시 읽기 실패: 「마지막으로 확인한 기록입니다」는 그대로 눈에 띄고, Host 가 준 오류 원문은 「오류 상세」로 펼친다. 같은 말을 진행 상자에 다시 적지 않는다.
- 판정 값 `failure` 는 「성공 미확인」으로 옮기고 원문은 상세에 남긴다(§1.2 — 반증으로 번역하지 않는다).
- 바닥 줄은 「읽기 전용」만. 좁은 화면에서는 머리줄 손잡이가 아래로 내려가 가로 스크롤이 생기지 않는다.
