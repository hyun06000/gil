# 승인 패널 읽기 개선 — 합성 fixture 전후 캡처 (2026-11-17)

`mcp-app/plans.mjs` 승인 패널을 긴 제안·많은 항목에서 읽기 쉽게 고친 결과를 **같은 합성 fixture·같은 상태**로
개선 전(`before-*`, main `2b24746` 번들)과 개선 후(`after-*`)로 찍은 것이다. `mock-host.html`은 MCP Apps
handshake를 흉내 내는 **모의 Host**이며 `fixture.json`의 합성 제안(가상의 매출 표 분석 Chain, 실행 항목 10개)을
`gil_plan_review` 응답으로 돌려준다. 실제 프로젝트·사람·대화는 없다. 헤드리스 Chrome 캡처이므로
실제 Host(Codex·Claude Desktop) 화면 인수가 아니며, 이 캡처로 Host 인수를 통과 처리하지 않는다.

| 파일 | 상태(`?state=`) | 너비 |
| --- | --- | --- |
| `*-long-420` / `*-long-960` | 승인 대기 · 계획 v1 · 긴 명제·범위·항목 10개 | 420px(좁은 화면) / 960px fullscreen |

| `*-executing-420` | 승인된 계획 · 지금 열린 Cycle에 묶인 항목 D · 실행 기록 A·B·C | 420px |

달라진 것(패널 안에서만):

- 실행 항목이 한 줄 문장 덩어리(`남음 · A: 질문\n확인: 조건`)에서 카드로 바뀌었다. 첫 줄에 순번·id·기록 상태
  (`남음`/`실행함`/`지금 열린 Cycle`/`재시도 대기`/`연결됨`)와 기록 Cycle(`기록 cycle:C2`), 그 아래 문제(question),
  그 아래 `완료 판단` 라벨과 done_when. 원문은 한 글자도 줄이지 않는다.
- 명제(statement)에 `확인할 내용` 라벨이 붙고, 다섯 범위 요소는 600px 이상에서 라벨·본문 두 열로 선다.
- 집계 줄은 0인 항목을 적지 않는다. 실행 기록이 없는 새 제안에는 집계 줄이 없다(판정 문장이 항목 수를 말한다).
- 승인된 계획 화면의 현재 항목은 문장(`지금 열린 Cycle cycle:C5에 묶인 항목:`)과 항목 블록으로 나뉘고,
  닫힘·열림 미확인 안내는 별도 줄이다. `실행함`은 그대로 기록 단어이며 성공·완료로 바꾸지 않는다.
- 키보드로 승인하거나 응답이 유실된 뒤에도 초점이 문서 바닥으로 떨어지지 않고 패널 제목에 남는다
  (버튼 비활성화 전에 초점 위치를 읽는다).

검수한 것(모의 Host, 2026-11-17): 420px·960px에서 카드 겹침·가로 넘침 없음(DOM 측정), 배너 → `승인 화면으로`
클릭 → 승인 버튼 초점 → Enter 승인 → `gil_plan_decide` 1회·채팅 계속 요청 1회·token DOM/메시지 노출 없음 →
초점은 패널 제목. 응답 유실(`state=hang`)은 `저장 결과 불확실` → `다시 읽기` 뒤 새 버튼, 결정 재전송 없음.
scope/revision/digest/token 결속, 자동 조회의 무전송, 낡은 제안 거절은 `plans.test.mjs`가 고정한다.

다시 찍기: 저장소 루트에서 정적 서버를 띄우고
`mock-host.html?state=<상태>&w=420[&mode=fullscreen][&locale=ja][&bundle=<다른 monitor.html>]`을 연다.
`w`는 iframe 폭(헤드리스 Chrome의 최소 창 폭보다 좁은 화면용), `bundle`은 비교할 이전 번들이다.
